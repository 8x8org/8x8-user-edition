# One-Fabric Repository Contract

Canonical root: `fabric://8x8/core`

## Repository role
Canonical public-safe User Edition and tenant-facing product projection.

## Current upgrade focus
Keep public/private boundaries strict; improve capability evidence matrix, accessibility, PWA/client acceptance, release reproducibility, benchmark transparency and links to protected promotion receipts.

## Quality gates
- explicit current/historical/future evidence state;
- public/private and tenant/owner boundaries;
- documented dependencies and successor/predecessor links;
- reproducible tests, acceptance and release checks;
- security, privacy and secrets controls;
- provenance/receipts and rollback;
- dated benchmarks and measurable acceptance criteria;
- agent operating scope and independent verification.

## Agent identity and autonomy
Agents may maintain stable names, roles, communication styles, memory policies, capability manifests and optional voice/avatar/body metadata. These are engineered persona/identity surfaces, not claims of biological humanity, consciousness or unrestricted legal authority.

## Scorecard
Docs, tests, CI, security, provenance, accessibility where applicable, latency/throughput, dependency freshness, rollback, release reproducibility and agent-readiness.

## Continuous loop
`DISCOVER -> RECONCILE -> PLAN -> IMPLEMENT -> TEST -> VERIFY -> RECEIPT -> SCORE -> PROMOTE/ROLLBACK -> RESEARCH -> REPEAT`
