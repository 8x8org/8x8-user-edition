# 8x8 User Edition — Three-Gate Architecture V1

Status: FROZEN PRODUCT ARCHITECTURE
Canonical root: fabric://8x8/core
Public projection: 8x8 User Edition
Principle: functionally bounded, visually complete.

## Gate 1 — DISCOVER / 8x8
Cinematic public entrance using the shared 8x8 visual language: deep-space field, gold infinity/8x8 identity, electric-blue accents, concise product proposition, truthful release status, and clear entry actions.

No private owner controls, unverified operational statistics, financial-return claims, or privileged fabric capabilities are exposed.

## Gate 2 — IDENTITY / CONNECT
Create or recover the user's 8x8 identity; authenticate the carrier; establish tenant/authority boundaries; connect only supported wallets/services; present permissions and vault state.

Telegram identity must be server-validated before it is authoritative. Client-side Telegram projection alone is not canonical identity. Google/X and unsupported wallet providers remain hidden or explicitly gated until configured.

## Gate 3 — 8x8 WORLD / COMMAND CENTER
A unified modular command center derived from the approved visual references. Initial V1 modules:
- Agent
- World
- Game
- Wallet / Vault
- Radio
- Connect
- Profile

Future modules may appear only as clearly marked COMING SOON portals until independently verified: Studio, Research, Books, Markets, Business, Devices, Content, additional agents/worlds, and other estate capabilities.

## Shared carriers
One information architecture projects to:
1. Web / Vercel / PWA
2. Telegram Mini App
3. Android APK

Carrier-specific adapters may handle identity, safe areas, wallet handoff, navigation, and device capabilities, but they must preserve the same product model and release semantics.

## Visual system
Merge the approved reference concepts into one system:
- gold 8x8/infinity portal and premium identity
- black/deep-space environment
- electric-blue/cyan structural highlights
- central omniversal portal
- compact command-center cards
- One Fabric architecture language
- responsive mobile-first progressive disclosure

Do not reproduce fictional numbers, balances, agent counts, revenue, network health, trading performance, or other mock data as live production facts.

## Release boundary
The Minimal User Edition implementation remains the functional substrate. The Three-Gate shell is layered around it. Features become active only after their acceptance tests pass. Historical/full-estate UI remains donor/reference material, not automatically active public capability.

## V1 acceptance rule
"100%" means every REQUIRED item in the frozen User Edition V1 acceptance denominator has reproducible evidence. Gated future functionality does not masquerade as complete.

Required release evidence includes source identity, build/check results, carrier rendering, identity boundary, wallet behavior, game behavior, radio controls, payment/reservation fail-closed behavior, Android artifact provenance, security/public-boundary checks, and rollback evidence.

## Safety and authority
Owner-private fabric remains isolated. No seed/private keys are collected. No signing, fund movement, token minting, mainnet action, paid campaign spend, or legal acceptance occurs without the appropriate explicit authority and verified configuration.

## Delivery doctrine
Scope -> Architecture -> Dependencies -> Atomic Tasks -> ETA -> Implement Reversibly -> Test -> Verify -> Receipt -> Release -> Evolve.

Exactly five supervisory lanes remain authoritative. Event-driven execution beneath them is not a sixth scheduler.
