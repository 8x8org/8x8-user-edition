# MSG296E — 8x8 Fabric Mirror implementation generation

**Canonical product version:** `0.0.1 Beta`  
**Implementation identifier:** `MSG296E`  
**Status:** `SOURCE_CANDIDATE / PUBLIC_SAFE / DEPLOYMENT_VERIFICATION_REQUIRED`

MSG296E is implementation metadata, not product maturity. Historical references to earlier public slices remain provenance only and do not promote 8x8 above `0.0.1 Beta`.

## Why this rebuild exists

Earlier public slices did not represent enough of the accumulated 8x8 estate, and a historical deployment was observed serving an incorrect source artifact at `/` instead of browser-renderable HTML on mobile. MSG296E therefore treats routing correctness, public-boundary safety and whole-system reconciliation as release requirements.

## Three Realities

The Fabric treats the realities as native system state:

- `PRIVATE_PAST` — private operational history, evidence, memory, superseded implementations and recovery truth;
- `PUBLIC_PRESENT` — current privacy-safe, evidence-backed public projection;
- `FUTURE_LAB` — research, simulations, candidate capabilities and unpromoted prototypes;
- `PROTECTED_BETA` — transition state used to validate promotion into Public Present, not a fourth reality.

`CALLER_IDENTITY -> AUTHORITY -> SERAPHIM -> LATEST_GOOD_SNAPSHOT -> THREE_REALITIES -> ACTIVE_MISSION_DAG -> MEMORY/EVIDENCE -> MODEL_FABRIC -> TOOLS/CONNECTORS -> CONTEXT_BOOTSTRAP_RECEIPT`

Repeated public-demo runs are serialized: a previous interval is cancelled before a new run starts, and the trigger is disabled until completion. The browser demo is public-safe and does not fetch private runtime data. Universal runtime certification across every client/agent remains a separate evidence gate.

## Public/private boundary

Never publish owner credentials or private keys, wallet signing/recovery material, protected repository inventory, unrestricted raw messages/memory/logs, sensitive device topology or exact private locations, privileged control channels, or live financial execution authority.

The public interface may show sanitized public repository references, aggregate capability states and explicit VERIFIED / PARTIAL / PLANNED / BLOCKED labels.

Candidates to evaluate in bounded canaries include OpenTelemetry for traces/metrics/logs and GenAI semantics, CloudEvents-style event envelopes, W3C PROV lineage, A2A/MCP interoperability, graph semantic zoom, WebGPU/WebXR for advanced spatial presentation, Cesium-class planetary projection, C2PA for Studio/media provenance, TUF/Sigstore/SLSA for release integrity, CRDT/local-first patterns for non-authoritative collaborative UI state, and durable workflow/replay patterns for long-running missions. ## Deployment acceptance contract

A public release is not PASS until all of the following are demonstrated on the exact reviewed commit:

1. a Vercel project and deployment record tied to canonical User Edition source exists;
2. deployment state is READY;
3. `/`, `/first-blink`, `/world`, and `/art-board` return HTTP 200 browser-renderable HTML;
4. `Content-Type` is `text/html` for route documents;
5. no `Content-Disposition: attachment` is emitted;
6. the response body is HTML, never an accidentally selected source artifact;
7. logged-out access works without preview authentication for the public alias;
8. Android Chromium smoke passes;
9. iPhone/mobile Safari smoke passes;
10. security headers and public-information-boundary checks pass;
11. no private topology, protected inventory counts or secret material is present;
12. exact project ID, deployment ID, source commit and rollback target are recorded in a deployment receipt.

## Version drift rule

Public product maturity is fixed at `0.0.1 Beta` until explicit owner-approved system-wide promotion. Validation must fail if current public source introduces `v0.1.1`, `0.1.0-beta`, `0.1.x`, `stable`, `1.0`, or equivalent product-maturity claims outside historical/provenance allowlists.
