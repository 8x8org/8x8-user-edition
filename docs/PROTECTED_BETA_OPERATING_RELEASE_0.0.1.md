# 8x8 OS Protected Beta Operating Release 0.0.1

**Product maturity:** 0.0.1 Beta  
**Reality:** PROTECTED_BETA transition toward PUBLIC_PRESENT  
**Canonical source:** `8x8org/8x8-user-edition`  
**Program:** MSG311

## Purpose

Turn the public Omniversal Command Atlas from a public-safe architectural projection into a progressively functional user product without falsely promoting unfinished private, financial, identity, device, or Future Lab capabilities.

The operating release is organized around one Fabric and one evidence chain. Public functionality advances only when its backing service, tests, security boundary, rollback, and deployment receipt exist.

## User operating path

The intended protected-beta path is:

1. create account;
2. verify account ownership;
3. create or recover a permanent 8x8 ID;
4. create an isolated user profile and workspace;
5. review permissions and privacy defaults;
6. enter First Blink;
7. load the public-safe Reality / Proof Graph;
8. use bounded agents, tools, knowledge, Studio, research, and public services;
9. enroll optional devices or connectors separately;
10. access economy, wallet, token, NFT, node-contribution, or other regulated/high-impact functions only after their independent gates exist.

## Account and 8x8 ID contract

A real account system must provide:

- globally unique internal user ID;
- user-selected public handle independent from internal ID;
- permanent 8x8 ID identifier with recovery and revocation semantics;
- verified email or equivalent account recovery channel;
- passkey/WebAuthn support as the preferred authentication upgrade;
- session expiration and device-session visibility;
- profile privacy controls;
- delete/export account workflows;
- rate limits and abuse controls;
- database row-level isolation;
- audit events for identity-critical changes;
- no owner/private runtime credentials exposed to users;
- no implicit wallet, node, telemetry, or financial consent from account creation.

The current static User Edition MUST NOT claim these properties are live until the backing identity service is deployed and verified.

## Functional release gates

A capability becomes PUBLIC_PRESENT only after all applicable gates pass:

- source merged from current main;
- exact-head validation passes;
- public-information boundary passes;
- security tests pass;
- accessibility gate passes for UI;
- browser smoke tests pass for UI;
- SBOM/provenance generated for release artifacts;
- receipt binds source, artifact, deployment, and public claim;
- rollback exists;
- production route is verified;
- private data and private topology remain denied;
- regulated or financial capability has its separate legal/compliance/custody/owner authorization.

## Dormant-work convergence

Historical repositories, dashboards, PRs, scripts, media, agents, world experiments, economy prototypes, Quran/Planet Earth work, BTC research tools, Studio assets, and device integrations are not discarded. They enter the Fabric through:

`DISCOVER → HASH → CLASSIFY → DEDUPLICATE → PROVENANCE → SENSITIVITY → MAP → PORT/UPGRADE/SUPERSEDE/ARCHIVE → TEST → RECEIPT → REALITY-PLACE → PROJECT`

No stale implementation may overwrite newer 0.0.1 truth merely because it has more features.

## Economy and digital assets

Economy, token, coin, NFT, wallet, governance, rewards, node contribution, staking, marketplace, and settlement concepts remain inside the Fabric but are not promoted by this release merely because historical UI or research exists.

Before real purchase, minting, issuance, custody, swap, staking, trading, or autonomous signing can be PUBLIC_PRESENT, the specific lane must independently prove contract identity, network, supply/accounting rules, custody design, user disclosures, jurisdiction/compliance review where applicable, security review, transaction simulation/testnet evidence, rollback/incident plan, and explicit owner promotion.

Public UI must never convert a simulated button or historical token table into a live financial claim.

## 100/100 definition

For 0.0.1 Beta, `100/100` means complete evidence coverage for a named release scope at an exact timestamp. It does not mean the Future Lab is exhausted, the Fabric can never improve, or every planned capability is already deployed.

A user-facing operating release may reach 100/100 for its declared protected-beta acceptance contract while the whole evolving 8x8 estate remains 0.0.1 Beta.
